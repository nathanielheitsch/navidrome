Progress send waits must observe cancellation or receiver closure. Sink disconnection policy must be chosen (recommend cancel scan + drain/join; not detached work). Do not block a DB transaction on an observer or event broker.

### Transaction/retry/time rules

DB owns transactions and busy retry; **scanner does not add a second retry loop**. Current retry budget is 3 retries / 4 attempts (`nd-db/src/store.rs:20-24,116-144`), with busy/locked classification there. Filesystem, tag reading, playlist parsing and external events occur outside retryable closures. Scanner obtains immutable prepared input before opening a transaction, reconstructs mutable attempts from it, and publishes IDs/counters/image collectors/warnings only after a committed outcome. Preserve Go's operation-specific best-effort artwork/annotation behavior without allowing a caught error to hide a poisoned/rolled-back transaction; error contract must support this, or a reviewed deviation is required.

Per-folder commit is the phase1 unit; never one transaction over an entire tree. Per move, per album refresh, phase1 missing-folder finalizer, GC and final library updates have their own transactions as below. Repos within a transaction borrow that transaction's connection; never recursively check out SQLStore. Stable cursors release leases before writes when required by DB API. No SQLStore lease across filesystem await/backpressure. Cancellation: stop producers, finish/rollback any started DB operation according to DB contract, join it, then release scan lock; no ScanEnd or PID stamp on partial/failing run. Do not claim an aborted tokio handle rolled back blocking SQLite.

Use typed UTC instants and the DB-owned encoder. `created_at` unset is `None` until DB Put stamps it; file `updated_at` is actual mtime, **not scan time**; birth_time is required by MediaFileRecord, so storage fallback is explicit (Go tries birthtime then statx then now, `local.go:120-153`). Preserve original created_at/birth_time on updates via DB Put; no invented zero-size, zero timestamp, bit depth or default library. Empty strings are legitimate values where Go permits; `NULL`, missing projection, malformed stored JSON and no row remain distinct. Generated IDs are nondeterministic but stable after persisted PutByMatch. No ID must escape a rolled-back attempt.
