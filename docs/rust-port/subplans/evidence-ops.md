### Construction versus task dependencies

- Constructors live in BOOT/nd-cli: they inject concrete database, filesystem, HTTP, provider, scheduler and service implementations. Libraries expose narrow contracts; no API/service crate imports nd-cli just because Go wire generated that object.
- Cyclic runtime acquaintances become interfaces and phased tasks, not cyclic Rust dependencies: playlist parser→DB import service→SC phase4; scanner enqueues artwork→worker consumes it, but image primitives can be built before scanner; scrobbler consumes provider capability/error identity, not an entire agent fleet.
- “No route shipped until dependency gate” is different from “no contract work can start.” #18/#21 pure codec/matcher/spec lanes can be scoped independently; full services remain blocked until their listed contracts are reviewed.
- Unrelated tails (FTS repair, complete maintenance/logging, metrics, jukebox, full CLI/share HTML) do not automatically gate a one-track authenticated lookup/stream. If minimal route relies on a specific residual, that method gate becomes explicit instead.
