## 2. Shared proposed wire contract (must be frozen by API-00 BEFORE handlers)

These exact recommendations are not claims that every path/body already exists in Go. Native CRUD provenance is `server/nativeapi/native_api.go:59-119`, pinned deluan/rest v1.0.1 (`go.mod:12`); new routes provenance is the product decision + Go semantic transcription.

### Mounts, auth and errors

* BasePath is an exact segment prefix, applied once. Outside prefix: 404; root AND prefix-root: 404. No SPA fallback or redirect. Recommend no redirect on trailing slash; explicitly register both native CRUD forms if captured Go accepts both, and document one canonical OpenAPI path. Avoid method-changing 301/302 on login/PUT. Unsupported methods on a registered resource: 405 + Allow; removed routes remain 404 even when authenticated.
* Recommend canonical session transport `X-ND-Authorization: Bearer <JWT>`; new key transport `X-ND-API-Key: nds_<22 base62>`. **Decision gate** on the new key header and on cookie/jwt-query policy. Recommend header-only at mounted canonical boundary: no password, API key or JWT in URLs/cookies; explicitly presented unsupported/malformed credentials must not silently bypass via ExtAuth/dev login. Current verifier accepts cookie/query jwt; change needs #13 owner approval. Do not silently retain an auth-in-query contract while saying it was dropped.
* Multiple supplied credentials: reject disagreement; if allowing agreeing combinations, verify **every** JWT's signature, issuer, native audience, expiry, uid and epoch, and each key's actual owner. Same username is insufficient if one token has stale ep/old uid. Repeated security headers should be rejected rather than HeaderMap::get selecting one. Untrusted external-user headers neither authenticate nor manufacture conflicts.
* API principal is server-owned user ID/username/admin/current epoch plus optional authenticated player ID and credential kind; no password/hash in DTO/log. Reload current user for JWT/key on each request. Keys remain valid across epoch bumps, but cannot survive owner deletion. Forbid forging internal-auth from any HTTP header/query.
* Recommend JSON native errors `{ "error": "<stable public text>" }`, content-type application/json. Validation uses Go native `{ "errors": { "field": "message-key" } }` where captured. Current nd-auth HTTP errors are plain text; centralize deliberate mapping or change #13 responses under ownership; do not claim existing golden agreement. Fixed public classes: 400 `Invalid request`; 401 `Not authenticated`; 403 `Permission denied`; 404 entity-specific capture text for native reads (song: `MediaFile(id:<id>) not found`); 409 `Conflict`; 413 `Request body too large`; 422 `Invalid request payload`; 429 `Too many attempts`; 500 `Internal server error`; shutdown admission 503 `Service unavailable`. Standard stream conditional/range errors retain their nd-stream text/plain body/header contract, not a Subsonic envelope. Stream launch cap: 429 + `Retry-After: 5` + `too many concurrent transcodes, please retry shortly` (choose JSON vs Go-style text for canonical launch errors in API-00; recommendation JSON with exact message). Never expose SQL, path, argon hash, raw token/key or ffmpeg stderr.
* Error precedence: route/method resolution -> credential parsing/verification -> user reload/current claims -> route privilege -> request decode/validation -> DB scope/query -> path authorization -> decision/open -> stream. Login guard obtains attempt slot before body parsing; auth request body hard cap 8192 bytes. Request syntax does not bypass authorization or reveal cross-library existence. General retained JSON/forms cap 10MiB (not upload caps); new key/revoke empty bodies require <=8KiB and reject nonempty unexpected objects. Malformed JSON=422, semantically invalid fields=400. A new recommended stricter duplicate/trailing-JSON rejection must be fixture-labeled, not attributed to Go decoder behavior.
